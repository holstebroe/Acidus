# Calibration against the dinsync.info x0x reference set (2026-09-28)

The `SynthParameters` defaults in `src/core/SynthEngine.hpp` were refitted to
the dinsync.info TB-303 reference recordings in `test/resources/x0x-reference`:
one hardware unit, 25 files x 16 notes, a systematic sweep of all five knobs,
both waveforms, with and without accent, and levels that are not normalised.
The set is described in
[`test/resources/x0x-reference/x0x_reference.md`](../test/resources/x0x-reference/x0x_reference.md)
and machine-readably in `x0x_reference_manifest.json`, both generated by
`tools/x0x_reference_manifest.py`.

## What the recordings establish

- Every note is **C2** (65.4 Hz), the keypad's lowest C, not C1. The unit is
  tuned **+5.4 cents** (one value for all notes; the per-note spread on
  clean notes is ~0.3 c).
- **One recording gain holds for all 25 files.** Settings recorded in several
  sets (e.g. all knobs at 50 % in C1-C5) repeat within 0.4 dB, so absolute
  levels are compared with a single gain.
- The notes sit on a fixed 3 s grid with a ~1330 ms gate. **Unaccented notes
  start sounding ~4.5 ms after accented ones**: the gate opens at the same
  moment, and the unaccented VCA shows only a faint click before opening. The
  model starts both at once and has no mechanism for this delay; it is left
  as a known difference (the fit's global note-on shift, ~1 ms, splits it).
- The **square is a 53.3 % pulse at C2**. The 15th harmonic is nulled and the
  first 16 harmonics match within ~1-2 dB with a duty of 0.533. The model's
  duty law is `0.45 + depth * exp(-f / 180 Hz)`; depth 0.12 gives 0.533 at
  C2 and 51.5 % at 110 Hz, which also satisfies the sourced "close to
  symmetric around 100-120 Hz". This value was set by measurement: the
  search stalled in a local minimum at 0.24.
- At **Cutoff 0 / Resonance 100 %** (A2 position 4) the unit shows almost no
  resonant peak: a +3 dB bump near 200 Hz that is gone once the note
  settles. This unit's cutoff range is therefore well below the ~314 Hz
  minimum of Open303's fit.

## Procedure

`tools/calibrate_reference.py --manifest`: CMA-ES over the model constants
and the knob positions (one fitted position per knob and chart percentage,
with a prior of 0.3 per (0.1 travel)^2 toward the chart value), one global
gain, a global note-on shift relative to each note's grid note-on. One
1.75 s note takes ~0.46 s to render, so the search used subsets:

| Stage | Notes | Window | Free | Result |
|---|---|---|---|---|
| 1 | quarter 0 (`--rotate 0`) | 800 ms | 60 | 5.59 -> 3.70 |
| square duty set by measurement | | | | held-out quarter 3.97 -> 3.27 |
| 2 | quarter 2 | 800 ms | 59 | 3.27 -> 2.81 |
| 3 | quarter 1 | full 1.75 s | 8 (resonance curve and gain, VEG decay, gate-off release, post-HP, timing) | 3.19 -> 3.04 |

Each stage started from the previous stage's values on a note quarter it had
not been fitted to. Parameters the 800 ms window or a single key cannot
constrain were held: the saw LPF/bend, notch, allpass, output coupling, MEG
attack, VCA saturation. All fitted knob positions stay within 0.03 of the
chart values, so the chart percentages are consistent with the fitted laws.

## Trade-off: the two hardware units disagree

The 13 older single-note samples in `test/resources` come from a different
unit. Scored with the new defaults they fit much worse: weighted error
2.42 -> 10.80, harmonic error 2.2 -> 6.0 dB. The loss is concentrated in their
Cutoff max / Resonance max notes (per-note error ~3 -> 15-21). That unit's
filter sits much higher: its c1r1 notes resonate around 3 kHz, while the x0x
unit at Cutoff 0 / Resonance 100 % barely shows a peak near 200 Hz. The two
units are trimmed differently (TM3 sets the cutoff range). The defaults now
follow the x0x unit, which has 400 notes across the whole knob space against
13 notes at knob extremes.

## Reference-conformance changes (`acidus_reference_test --fast`)

Before this calibration: 25 pass / 9 fail. After: **22 pass / 12 fail**.

- **Now passing: C3** (square duty at 110 Hz, 58.6 % -> 51.5 %).
- **Newly failing, supported by the recordings:**
  - **E1** (service calibration peak 268 Hz, target 400-670 Hz) and
    **E3** (Cutoff max settled peak 935 Hz, target 1800-3000 Hz). These
    targets are Open303's fit of another unit. The x0x recordings require the
    lower range (see A2 position 4 above), and the cutoff law fits the A1
    cutoff sweep's brightness within 2.0 dB (harmonic error).
- **Newly failing, a real model shortfall:**
  - **B4** (resonant peak +9.1 dB target, now -0.3 dB). The recordings
    also want stronger peaks. At all-100 % the hardware's peak stands
    +26 dB above the low harmonics at note start and +14 dB settled; the
    model gives +15 and +13 dB at the right frequency (2230 vs 2034 Hz).
    At Cutoff 75 % / Reso 100 % the settled peak sits too low (394 vs
    853 Hz). The E-row sets (E1, E3, E4), where this matters most, remain
    the worst-fitting.
  - **E6** (MEG sweep 4.48 oct vs >= 4.5): marginal.
- **Still failing, not addressed:** B6, C4 (saw/square level 1.50 vs
  1.6-2.6; the fitted square level follows the recordings), C5, D6 / E8
  (VEG decay: this unit's held notes decay more slowly than R123 x C42
  predicts, 2.35 s vs 1.2-1.5 s), E7, E9.

## Known gaps / next steps

1. **Resonance strength at note start** (B4, E-row sets): the peak is ~10 dB
   too weak during the attack of high-resonance, high-Env-Mod notes. That
   points at the feedback path rather than at a knob law.
2. `filterPostHpHz` sits at the calibrator's 200 Hz bound; the fit uses it to
   weaken the C2 fundamental (the hardware saw's 2nd harmonic is ~1.6 dB
   above the 1/k law). A physical explanation, such as the VCA-input coupling
   or output stage, would be better than a 200 Hz high-pass.
3. The **4.5 ms unaccented onset delay** is not modelled.
4. The x0x set only has C2, so nothing here constrains key tracking (e.g. the
   square duty's frequency law or cutoff tracking across the keyboard).
